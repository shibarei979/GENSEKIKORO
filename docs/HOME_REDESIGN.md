# 新デザイン (home_10) 移行レポート — v6

作成日: 2026-07-25（v2: サイト全体移行方式へ変更）

デザインデータ `home_10` を **サイト全体のデザインシステムとして** Next.js + Supabase 構成へ組み込んだ。
v1 の「トップページだけをスコープして例外扱いする方式」は廃止し、
テーマ・ヘッダー / フッター・基本スタイルはサイト共通、トップページはその上に載る1ページ、という構成に改めた。

## 2. テーマ / ビュー / ログイン状態の一元化

**旧サイトの `<html data-theme>` 方式と新デザインの2系統併存を解消**し、`<body>` の data 属性1系統に統一した。

| 属性 | 値 | 保存先 | 決定方法 |
|---|---|---|---|
| `data-theme` | `light` / `dark` | `localStorage("theme")` **（旧サイトのキーを継続 = 既存ユーザーの設定を引き継ぐ）** | layout の inline script が描画前に復元。切替はヘッダーメニューのトグル（site.js） |
| `data-view` | `reader` / `writer` | `localStorage("gsk_view")` | 同上。`data-set-view="writer"` 付きリンクでも切替 |
| `data-auth` | `guest` / `login` | — | **サーバー（layout.tsx）が毎リクエスト確定** |

- どのページで切り替えても body 属性と localStorage が更新されるため、**全ページで同期**する。
- 旧実装の `<html data-theme>` は復元スクリプトが除去して一本化（旧 globals.css の `[data-theme="dark"]` 変数群は body 属性にもマッチするため、**旧ページのダーク配色もそのまま動く**）。
- クライアント遷移では body が維持されるため属性が消えない（v1 のバグ原因を解消）。

## 3. 件数固定と「準備中」埋め（レイアウト不変）

作品が足りない場合もレイアウトは変えず、**末尾を「作品タイトル（準備中）」で埋める**（旧トップページと同じ考え方）:

| セクション | 固定数 |
|---|---|
| 本棚ループ | **25冊**（index 0〜24 固定。左右10冊 + 中央1冊 + 裏側） |
| Pick Up! / New Release! | **各10冊**（「更新」ボタンの再描画時も10冊固定。実データをシャッフル後、不足分を準備中で埋める） |
| 4カラムリスト（ログイン時） | **4列 × 各8冊** |

準備中の本は `data-placeholder` が付き、クリックしてもポップアップは開かない。

## 5. ⚠️ 依存関係の復旧（重要）

前回 `npm audit fix` により **Next.js が 16 へ誤更新**されています（searchParams エラー等の原因）。
このzipの package.json は正しいバージョン（next 14.2.35 = 14系最終セキュリティパッチ）に固定済みです。
**必ずクリーンインストール**してください:

```bash
rm -rf node_modules package-lock.json .next
npm install
npm run build
```

以後 `npm audit fix` は **実行しない**でください（`--force` 相当の破壊的更新が走ることがあります）。
脆弱性対応はバージョン指定の `npm install パッケージ@バージョン` で個別に行うのが安全です。

## 7. 既知の注意点・今後

- デザインの `*` セレクタ（明朝フォント・色）と `body { zoom: 0.9 }` がサイト全体に適用されるため、**他ページの見た目は新デザイン寄りに変わる**（意図どおり）。崩れが目立つページは順次調整。
- 旧ヘッダーにあった検索窓・通知ドロップダウンは新デザインに存在しないため廃止（ベルは通知ページへのリンク）。必要なら新デザインの文法で再実装する。
- 第1話本文の一括取得は作品数が増えたら RPC 化を推奨（v1レポート参照のSQL例は `docs/backup/` 側に残存）。
- いいね集計は対象作品合計1000行で頭打ち（旧トップと同方式）。将来は集計RPC推奨。
- Next 15/16 への移行は別課題（searchParams / cookies の Promise 化など広範囲の変更が必要）。

## 8. v3 での修正（フィードバック対応）

1. **ビルドエラー修正**: 旧ヘッダー / フッターに props（profile / user / activeGenre）を渡している既存ページが約20あるため、新 Header / Footer は互換 props を受け取って無視する形にした（呼び出し側の変更は不要）。
2. **ヘッダーのスクロール固定**: 元デザインの `#header { position: fixed }` を復活（新 Header は `<div id="header">` ラッパー付きで出力）。トップページは元デザインどおり背景に重ね、**他ページのみ**ヘッダー高さ分のスペーサー（160px / モバイル110px）で内容を下げる。
3. **色の一元化（茶色の上書き解消）**:
   - 旧 globals.css の `--color-*` 変数を**すべて新デザインパレット（--base-color-1〜5 / --main-color-1〜4 / --text-color）への参照に再定義**。例外は `--color-danger`（エラーの機能色）と `--admin-*`（管理画面）のみ。
   - 旧ダークモードの `header / footer / input を茶色にする !important 上書き`を削除・パレット化。**新デザインの配色は一切上書きされない**。
   - コンポーネント内の直書き色（#F26A21 等、62ファイル・約550箇所）もパレット変数へ一括置換。
4. **意図しないホバーアニメーションの除去**: 旧 globals.css の汎用ルール（`a { transition }` / `nav a:hover` / `button:hover { translateY }` 等）を削除。sub_nav のトグルと本棚の本が元デザインどおり静的になった。本棚の `.book` に命中していた旧作品カード用ホバー（`a[href*="/novel"]:hover > div`）も `:not(.book)` で除外。
5. **準備中の作者名**: プレースホルダの本は「作品タイトル（準備中）／作者（準備中）」で統一（4カラム含む全セクション、「更新」ボタンの再描画時も同様）。

## 9. v4 での修正（全ページの色味統一）

1. **背景キャンバスの全ページ化**: ライト=紙テクスチャ（bg-paper）/ ダーク=装丁（bg-binding）を Home 以外の全ページにも表示。`layout.tsx` が `<div class="bg">` を描画し、生成は `public/site.js`（背景モジュールを home.js から移動）。Home は元デザインどおりページ全体に敷き、他ページはビューポート固定（長大ページでのキャンバスサイズ上限対策。見た目はほぼ同一）。
2. **ヘッダー / フッターの配色統一**: ライト=ベースカラー1 / ダーク=メインカラー4。フッターは旧デザインメモの緑背景（main-color-3）から変更し、テキスト・ボタン・ロゴ（light/dark切替）も追従。ヘッダーは従来から同規則（70%透過でテクスチャを透かす）。
3. **テキストの原則**: ライト=テキストカラー / ダーク=ベースカラー1。色付き面（ブランド色ボタン等）の上はコントラストが高い側を採用する新変数 `--color-text-inverse`（ライト=ベースカラー1 / ダーク=メインカラー4）を導入。
4. **#fff の廃止**: コンポーネント内の `#fff / #ffffff / rgba(255,255,255,α)` を全廃（背景用途→カード変数、文字・枠用途→ `--color-text-inverse`、判別不能な箇所→ベースカラー1）。
5. **Tailwind のパレット化**: `tailwind.config.ts` のカスタム色（primary / bg / text 等）を CSS 変数参照に変更し、**ダークモードへ自動追従**するようにした。`white` はカード変数へ、`gray` 系もベースカラーへ再マップ。
6. **新規登録 / ログイン系ページ**: 上記により配色がパレット化・ダーク追従。外側の不透明背景を透過にし、背景キャンバスが透けるようにした（login / register / reset-password / update-password）。
   ※ **Google 連携の同意画面は Google がホストする外部ページのため色は変更不可**。アプリ名・ロゴは Google Cloud Console の「OAuth 同意画面」設定で合わせられる。
7. **bg-binding のコントラスト調整**（数値のみ）: 陰影の色振幅 20/21/22 → **34/36/38**、局所コントラスト pow 0.92 → **0.84**。物足りない / 強すぎる場合はこの4つの数値で微調整できる（`public/site.js` 内、コメント付き）。

## 10. v5 での修正

1. **フッター配色（確定仕様）**: ライト=**メインカラー2** / ダーク=メインカラー4。テキスト・ロゴは常にベースカラー1、白ボタン（作品を投稿する）は明地に緑字 / ダークでは明地に濃字。
2. **works「更新」ボタンのダーク時色**（元 home_10 の不具合修正）: `stroke="currentColor"` は path 要素側の color で解決されるため、`* { color: --text-color }` に負けて svg への指定が効いていなかった。path 側にも色を当てる修正ルールを works.css 末尾へ追加し、ダークでベースカラー1になるようにした。
3. **背景キャンバスが他ページで見えない問題**: 原因はページ最上位ラッパーの不透明背景（`minHeight:'100vh' + background: var(--color-bg / --color-bg-card / 直書き)`）。**35ページ**を透過化し、検索・ランキング・マイページ・作品ページ等でもキャンバス（ライト:紙 / ダーク:装丁）が表示されるようにした。描画されない場合のフォールバックは body の背景（ライト=ベースカラー1 / ダーク=メインカラー4、style/home/base.css がサイト全体に適用）が担う。
4. **テーマが勝手にライトへ戻る問題（マイページ等）**: React によるレイアウト再描画などで body の data 属性がサーバー初期値（light）に巻き戻るケースへの恒久対策として、site.js に**保存値の適用 + MutationObserver 監視**を追加。localStorage の保存値と食い違う書き換えを検知した瞬間に復元する（全ページ共通の保険。トグル操作は保存→反映の順なので干渉しない）。
5. **コントラスト精査**: Tailwind の gray 系をテーマ追従の意味変数（bg-card / brand-border / text-muted 等）へ再マップ。旧パレットの名残の直書き（#77706A / #B8AEA8 / #F5B080 / #F3ECE5、非 admin 34ファイル）もテーマ追従変数へ置換。機能色（赤=エラー / 緑=成功 / 青=情報 / 琥珀=警告）と管理画面は据え置き。個別ページで気になる組み合わせが残っていれば、該当ページ・要素の指摘で個別調整する。

## 11. v6: 新版 home_10 への差し替え

デザイン更新版 home_10 を同じパイプラインで再組み込みした。

**デザイン側の変更（そのまま反映）**
- 本棚ループ: 20冊 → **25冊**（layout_calc.js の B_SIDE_COUNT 8→10、CENTER_MARGIN 300→200）。`page.tsx` の SHELF_COUNT も 25 に更新（不足分は従来どおり「準備中」で埋める）
- works セクション: 見出し（w_head）が左カラムになる新レイアウト（幅 1800px・flex 配置）。マークアップは同一のためコンポーネント変更なし
- guide / notice / reading_list の余白・罫線調整、bookshelf の高さ調整
- **v5 までにこちらで当てた修正がデザイン本家に取り込まれた**: footer 配色（ライト=メインカラー2 / ダーク=メインカラー4）、works 更新ボタンのダーク時色（path への指定）、bg-binding のコントラスト数値（34/36/38・pow 0.84）。これに伴い組み込み側の重複パッチは撤去し、生成スクリプトを build_home_js4.py に更新

**変わっていないもの**: index.html の構造・セクション順・本の統一フォーマット・components/header.html・footer.html・画像。React コンポーネントと DB 連携はそのまま。
